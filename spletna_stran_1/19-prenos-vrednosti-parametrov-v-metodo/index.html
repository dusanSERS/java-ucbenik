Prenos vrednosti parametrov v metodo

Opis:Zaključek:Zaključki o metodah:Podpis metode (Method signature)Preoblaganje metod - method overloading (function overloading)PovzetekUvod (motivacija)Razlaga pojmaPrimer programaMetoda main

Pri klicu metode se izvajanje programa prenese na mesto, kjer je metoda definirana. Metoda za svoje delovanje pogosto potrebuje parametre, zato se ob klicu v metodo prenesejo tudi vrednosti teh parametrov.

Za izvajanje programa skrbi JVM, ki za delo uporablja delovni pomnilnik (RAM). Pomnilnik pri tem logično razdeli na sklad (stack) in kopico (heap).

Sklad (stack) je del pomnilnika, kjer se shranjujejo klici metod in njihove lokalne spremenljivke. Upravljanje sklada je samodejno in zelo hitro, podatki pa se odstranijo takoj, ko se metoda konča.

Kopica (heap) je del pomnilnika, kjer se ustvarjajo objekti (npr. polja in objekti razredov). Do teh objektov dostopamo preko referenc, ki so shranjene v spremenljivkah.

Spremenljivke na skladu lahko vsebujejo vrednosti primitivnih tipov ali reference na objekte, ki se nahajajo na kopici. Objekti na kopici ostanejo v pomnilniku, dokler jih ne odstrani garbage collector.

Zaključek:

Pri klicu metod, ko je argument objekt, se v metodo prenese referenca. Posledično se spremembe, ki jih nad parametrom metode (objektom) delamo v metodi izven metode poznajo.

Pri klicu metod, ko je argument primitivna spremenljivka, se v metodo prenese vrednosti. Posledično se spremembe, ki jih nad parametrom metode delamo v metodi izven metode ne poznajo.

Zaključki o metodah:

  • v metodi ni branja (System.in) in izpisa (System.out), razen če ni posebej zahtevano v nalogi oz. če je to namen naloge

  • metoda lahko vrne eno vrednost

  • če želimo vrniti več vrednosti uporabimo polje

  • vrednost, ki jo metoda vrne, lahko shranimo, izpišemo, drugače uporabimo

  • metoda naj opravljajo samo delo, ki ga morajo.

Preoblaganje metod - method overloading (function overloading)

Cilji učne ure

Povzetek

  • razumeti pojem preoblaganja metod

  • razumeti, kaj je podpis metode

  • znati napisati več metod z enakim imenom in različnimi parametri

  • razumeti, katero metodo Java izbere

Po koncu ure dijaki razumejo, da ima lahko razred več metod z istim imenom, če se razlikujejo po parametrih.

Uvod (motivacija)

Predstavljajmo si kalkulator.

Kalkulator zna:

  • sešteti dve števili

  • sešteti tri števila

  • sešteti decimalna števila

Operacija je vedno seštevanje, zato bi bilo nelogično imeti metode:

sestejDveStevili()

sestejTriStevila()

sestejDecimalna()

Veliko bolj logično je:

sestej()

in Java sama ugotovi, katero metodo mora uporabiti.

Temu rečemo preoblaganje metod.

Razlaga pojma

Preoblaganje metod pomeni, da ima lahko razred več metod z istim imenom, vendar z različnimi parametri - torej z različnim podpisom.

Primer programa

public class Kalkulator {

static int sestej(int a, int b) {

return a + b;
}

static int sestej(int a, int b, int c) {

return a + b + c;
}
}
 
public class Kalkulator {

static int sestej(int a, int b) {

return a + b;
}

static int sestej(int a, int b, int c) {

return a + b + c;
}

static double sestej(double a, double b) {

return a + b;
}
public static void main(String[] args) {
System.out.println(sestej(2,3));
System.out.println(sestej(2,3,4));
System.out.println(sestej(2.5,3.1));
}
}
